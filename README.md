# wasm-boids

C++ / WebAssemblyで魚群の挙動を計算し、Three.jsで描画するブラウザ向けシミュレーション。
局所相互作用から生じる集団運動と、数万匹規模での実行を両立することを目的とする。

[デモ](https://tokachi269.github.io/wasm-boids/)

| 項目 | 内容 |
| --- | --- |
| シミュレーション | C++ / WebAssembly |
| 描画 | Three.js / InstancedMesh / LOD |
| 対象規模 | 数万匹の魚群 |
| 設計上の重点 | 局所相互作用、再現可能な検証、実測に基づく性能改善 |

## このプロジェクトについて

基本的なBoidsの分離・整列・凝集を土台に、魚群の回転、捕食者への反応、群れから離れた個体の復帰を扱う。群れ全体を一つの中心へ強く引き寄せて形を作るのではなく、少数の近傍との局所相互作用を中心に構成する。

大規模な個体群の計算には、石橋・吉田による階層的Boidアルゴリズムの考え方を参照した。回転魚群については、Ito・Uchidaによる、限定された近傍との局所相互作用から三次元の回転クラスターが形成されるモデルを参考にしている。

論文実装の忠実な再現ではない。ブラウザでの対話的な実行を前提に、近傍記憶、クラスター追跡、捕食者、姿勢制御、描画用LODを組み合わせた独自実装である。

## シミュレーションの考え方

### 局所相互作用

各個体は視野と距離の条件を満たす近傍から、分離・整列・凝集の力を受ける。参照数は `maxNeighbors` で制限し、全個体の平均方向や重心を通常の群泳規則には使用しない。

近傍は毎フレーム選び直して即座に総入れ替えするのではなく、個体IDと経過時間を保持する。記憶中の寄与は寿命に応じて減衰するため、近傍の境界を横切っただけで力が不連続に切り替わりにくい。

近距離では魚体寸法を基準にした反発を加える。これは群れを広げるための一般的な分離とは別に、個体同士の深い重なりを避けるための処理である。

### 群れ全体の推定と復帰補助

空間階層の葉から小クラスターを推定し、近接する小クラスターをまとめて大クラスターとして追跡する。大クラスターは群れ全体の位置を推定するための状態であり、群れ形状を直接生成する主規則ではない。

大クラスター引力は、局所相互作用だけでは戻りにくい外縁の個体や、過度に広がった群れへの補助として使う。最も近い大クラスターを選び、その外縁から凝集範囲の外側へ向けて影響を減衰させる。さらに中心距離、局所的な近傍充足率、クラスターの追跡確度、捕食者による脅威で強さを調整し、すでに群れの内部にいる個体への介入を抑える。

### 捕食者への反応

捕食者を検知した個体は逃避方向と脅威状態を持つ。脅威は時間とともに減衰し、逃避中は速度と旋回能力を一時的に変化させる。捕食者側は対象の追跡と休止を持つが、通常魚の局所的な群泳規則とは分離している。

### 時間と姿勢

近傍寿命、脅威の減衰、ストレス、クラスターの追跡など、時間に意味がある量は経過時間に基づいて更新する。描画フレームレートが変わっただけで、群れが系統的に収縮・膨張しにくい状態を目標とする。

一方、木構造の再構築、クラスター計算、配列の並べ替えなどの保守処理はフレーム単位で間引く。低いフレームレートで保守処理の回数まで増やし、負荷を悪化させないためである。

姿勢は目標方向への回転トルク、移動距離あたりの最大曲率、水平化トルクで制御する。速度変更によって旋回半径が不必要に崩れないことと、急な向きの反転を避けることを重視する。

### 1ステップの処理

1回の更新では、全個体が同じ時点の状態を参照して相互作用を計算し、次の状態を別バッファへ書き込む。クラスター推定や木構造の保守は同じ更新経路にあるが、負荷を抑えるため必要なフレームだけで実行する。

```mermaid
flowchart LR
    A["読み取りバッファ<br/>位置・速度・姿勢"] --> B["空間階層を走査<br/>葉と境界を取得"]
    B --> C["局所相互作用<br/>分離・整列・凝集<br/>近距離反発・復帰補助"]
    C --> D["捕食者の影響"]
    D --> E["運動更新<br/>速度・位置・姿勢"]
    E --> F["書き込みバッファ"]
    F --> G["読み取り側と書き込み側を交換"]
    G -. "一定周期" .-> H["小・大クラスターを更新"]
    G -. "一定周期" .-> I["木構造を再構築"]
    I -. "設定周期" .-> J["空間順に配列を並べ替え"]
```

## 大規模化のための構造

### 空間階層と少数近傍

全個体間の相互作用は $O(N^2)$ となるため、空間的に近い個体を木構造の葉へ分割する。通常は同じ葉の中から少数の近傍を選び、不足時だけ交差する周辺の葉を検索する。

木構造の完全な再構築は毎フレーム行わず、局所的なsplit / mergeと組み合わせる。更新量を分散し、再構築による処理時間の突出を抑える。

### データ配置

位置、速度、姿勢、種族、ストレスなどはC++側のSoAに保持する。位置・速度・姿勢には読み書き用の二つのbufferを用い、全個体が同じ時点の状態を参照してから次の状態へ入れ替える。

近傍キャッシュは魚ごとに `maxNeighbors` 分の連続区間を持ち、有効な要素を区間の先頭へ詰める。近傍インデックス、経過時間、安定したslotを一つの要素として保持する。

木構造の再構築後は種族ごとの領域を維持したまま、葉の走査順に物理配列を並べ替える。近接する個体をメモリ上でも近づけ、相互作用計算時の局所性を改善する。安定した個体IDと格納インデックスは分離し、近傍、捕食対象、木構造の参照インデックスも同じ対応表で更新する。

### C++ / WASMから描画まで

```mermaid
flowchart LR
    A["C++<br/>魚群計算・SoA・空間階層"] --> B["WebAssembly memory<br/>位置・速度・姿勢"]
    B --> C["JavaScript<br/>typed-array view"]
    C --> D["Three.js<br/>InstancedMesh・LOD"]
    D --> E["水中fog・SSAO・Bloom"]
```

JavaScriptは位置・速度・姿勢のWASMメモリを `Float32Array` として参照し、描画用のインスタンス属性へ詰める。魚は距離に応じてLODを分け、通常魚は `InstancedMesh` で描画する。水中fog、SSAO、Bloomなどはシミュレーション状態を変更せず描画側で処理する。

## 品質と性能

性能上の変更は、速くなりそうという推測だけでは採用しない。先に処理区間の計測やサンプリングプロファイラで対象を絞り、同じ条件のA/Bベンチマークでフレーム全体の差を確認する。メモリ局所性や命令数の改善だけでは、総実行時間が改善した根拠にならない。

挙動を変えない最適化では、Release、固定seed、固定dt、1 taskのnative benchmarkでシミュレーションchecksumの一致を確認する。物理配列の並べ替えには、安定した個体IDを基準にした前後状態と参照インデックスの検証を用意している。並列実行は浮動小数点演算順が変わるため、性能測定とビット一致判定を分ける。

native benchmarkは相互作用、運動更新、木構造の構築、配列の並べ替え、クラスター更新などのCPU区間を測る。browser benchmarkはWASMシミュレーション、JavaScript側のインスタンス構築、描画命令の発行、GPU timer queryを分離する。実画面のFPSはフレーム到着間隔であり、CPU時間とGPU時間の単純な和ではない。

測定条件とコマンドは [`scripts/bench.md`](scripts/bench.md)、変更ごとの検証基準は [`docs/testing.md`](docs/testing.md) を参照。

## 主要パラメータ

ワールド座標の1単位は1 mとして扱う。各値は独立ではなく、近傍数、作用範囲、旋回能力の組み合わせで群れの形が変わる。

| 対象 | 主なパラメータ | 役割 |
| --- | --- | --- |
| 局所的な群れ | `cohesion`, `separation`, `alignment` | 凝集、分離、進行方向の整列 |
| 作用範囲 | `cohesionRange`, `separationRange`, `alignmentRange` | 各相互作用が届く距離 |
| 近傍 | `maxNeighbors`, `tau` | 参照数の上限と近傍IDの保持時間 |
| 移動と旋回 | `maxSpeed`, `maxTurnAngle`, `torqueStrength` | 速度上限、最大曲率、方向応答 |
| 姿勢 | `horizontalTorque`, `lambda` | 水平化と速度減衰 |
| 大クラスター復帰 | `schoolPullCoefficient`, `schoolPullStartDistance`, `schoolPullFullDistance`, `schoolPullDenseScale` | 復帰力、作用開始距離、引力が最大になる距離、密集時に残す倍率 |
| 捕食者 | `predatorAlertRadius`, `maxEscapeWeight`, `baseEscapeStrength`, `threatDecay` | 検知距離、逃避の優先度と強さ、脅威の減衰 |

まず局所的な3規則と作用範囲を合わせ、その後に旋回と姿勢を調整する。大クラスター引力は、群れの形を作る強さではなく、離脱個体を戻せる最小限の値から調整する。`maxNeighbors` は挙動とCPU負荷の両方を変える。

## 構成

| 領域 | 主な責務 |
| --- | --- |
| `src/wasm` | 個体更新、空間階層、近傍キャッシュ、クラスター、WASM binding |
| `src/simulation` | WASMの初期化、buffer view、シミュレーションstep |
